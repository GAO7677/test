# 数据中台全板块逻辑审计（2026-10-13）

结论：已有原始数据、版本、预处理、少样本生成和下载框架，但“任务完成”还不能等同于“产物语义正确、标注有效、满足需求”。优先修复数据覆盖、坐标/字符偏移、标签兼容和数据标签版本绑定，再补算法能力及体验。

本次仅审计，**没有修改业务代码、数据库 schema 或生产数据，没有启动训练/GPU，也没有重启服务**。修改建议与验收条件见 [TODO_LOGIC.md](TODO_LOGIC.md)。

## 1. 核查范围和证据

- 逐项检查数据获取层、数据预处理层、可视化/标准层、系统管理以及场景供数 API，覆盖当前导航的全部板块。
- 本地与 118 的 85 个后端/前端源码文件哈希一致；审计对象是当前部署代码，不仅依据原 README 的功能描述。
- 生产只读盘点：图像原始记录 10 个、视频 12 个、文本 13 个，语音与雷达均为 0；预处理数据集 37 个、版本 57 个。少样本 #1 failed、#2 completed；#2 有 8 张空检测标签，空框不自动等于失败，也不等于已确认负样本。
- 在 118 独立 SQLite、微型合成文件上执行 **23 个后端 CPU 复现样例**；另从当前 Vue 源码提取函数执行 **6 个前端逻辑探针**。所有探针确认所列现象，并不是业务验收“29项通过”，也不是29个互不重叠的问题。
- 视频短例使用真实 CPU 编码/解码，目标检测器用桩测试帧调度；800秒长例用模拟 VideoCapture 检查截断，不声称做了长片检测质量评估。前端探针不是完整浏览器操作。
- 真实模型精度、生成质量、ASR/雷达物理准确性、生产并发压力及所有真实文件格式未在本轮验证。没有真人音频/雷达输入；没有下载模型或使用 GPU。
- 证据目录：`/data/gaoya/agent-data/outputs_v1/data_platform3_linux/20261013_platform_logic_audit/`；118 对应 `/mnt/data/gaoya/agent-data/outputs_v1/data_platform3_linux/20261013_platform_logic_audit/`。

证据文件：`findings.json`、`reproduction_results.json`、`ui_probe_results.json`、`runtime_inventory.json`、`local_source_hashes.json`、`remote_source_hashes.json`、`source_locations.json`；复现脚本和日志同目录保留。

## 2. 各种数据应该怎样处理

处理流程应按“任务目标 + 产物类型 + 标注单位”选择，不能只依据文件扩展名。`image/video/text/voice/radar/mixed` 是来源模态；`原始/已标注/清洗后/转换后/采样后` 是阶段；原文件、特征向量、帧图像和标签表又是不同产物。

| 数据/目标 | 标注单位与必要字段 | 当前能力 | 建议处理顺序 |
|---|---|---|---|
| 图像目标检测 | 每张图的 bbox、类别、原尺寸、坐标格式 | COCO80检测与手动画框已实现；缩放标签存在错位 | 解码/去损坏与重复 → 标签与类别映射 → 自动框 → 人工核验 → 联动变换 → 按来源划分 → 导出 |
| 图像分类/分割 | 分类是整图类别；分割是 mask/polygon，不能用检测框代替 | 原生分类标签可导入；当前人工分类/分割选择未切换成对应工具，SAM3占位 | 按任务分开表单/schema；未实现的工具明确禁用；caption作为训练文本单独保存 |
| 视频目标检测/跟踪 | 约定帧集合的 frame_index/PTS/bbox；跟踪另需 track_id、可见性 | 默认稀疏抽帧，人工按暂停时间点画框；没有身份跟踪传播 | 解码与时基确认 → 按视频/场景划分 → 明确抽帧或逐帧 → 框/轨迹标注与核验 → 保留帧源关系导出 |
| 视频分类/动作或事件 | 整片类别或时间段 start/end/event；不必每帧画目标框 | 当前关键帧/运动记录不等于完整事件标注 | 定义片段与事件类型 → 时间区间标注 → 按视频/主体分组 → 输出区间清单 |
| 语音 VAD/转写 | 时间段 start/end、文本、说话人（如需要）；词级任务需词级时间戳 | VAD/波形基础能力；Whisper路径错误且依赖缺失，转写修正不完整 | 可解码音频 → 规范解码视图/保留原时基 → VAD → ASR → 听取并修正文本/边界 → 按录音/说话人分组 |
| 自然语言文本 | 规范化文本视图、实体start/end/类别或文档分类；明确编码与偏移单位 | 规则实体/关键词/分类有实现；自动标签与人工/下载有断点 | 编码与换行视图 → 清洗及offset_map → 实体/分类 → 人工修正 → 结构化导出 |
| CSV/JSON/XML结构化文本 | 记录ID、schema、字段路径、数值类型；文本字段才做NER | 当前大量按原始文本或行处理 | 先解析结构 → 字段/记录清洗与类型检查 → 按选定字段标注/数值处理 → 验证结构 → 导出 |
| 雷达点云CSV/PLY | 坐标系、单位、timestamp，以及真实intensity/RCS/velocity等字段 | 有几何展示/简单筛选/聚类；部分物理含义是近似，字段会丢失 | 字段/物理定义 → 点云校验 → 合适的几何/强度算法 → BEV/3D核验 → 关联变换 → 按序列划分 |
| 多模态集合或特征 | 每个文件/样本的modality、artifact_type、来源与关联键 | 当前主要是分目录复制，未真正融合 | 先分别完成各子模态校验 → 按样本/时间键对齐 → 仅执行已实现的融合 → 保留各来源与schema |

补充原则：验证/测试集先按来源冻结。会拟合参数的标准化、词表、模型训练和AIGC补充只使用训练侧；相邻视频帧、镜像内容、同一对象或生成任务不应任意散入不同集合。

## 3. 视频专项：首帧、抽帧、逐帧要分清

| 入口/算法 | 现在实际做什么 | 不能据此宣称什么 |
|---|---|---|
| 视频获取页“预览” | 读取首帧缩略图和时长/FPS等元数据；不播放标注序列 | 不能据此认定视频只标首帧，也不能检查全片标签 |
| 视频可视化 | 至多读取前300帧，选部分缩略图、计算帧差；不是完整标注播放器 | 不等于全片分析；长片前段以外未覆盖 |
| COCO自动标注 | `frameInterval=2`为秒，约每2秒检测一次；含第0帧，最多200个采样帧；仅有框的帧写入items | 不是默认逐帧检测，也不是目标跟踪；短于2秒的片段可能确实只检测第0帧 |
| 关键帧/运动/场景规则 | 帧差，最多前2000帧；关键帧是时间记录，未导出成新的图像数据集；最多存1000条item | “目标跟踪”没有对象身份/光流轨迹，“场景分段”没有完整起止段 |
| 人工视频工作台 | 用户暂停/跳转后画框，记录当前time；显示容差±0.5秒 | 不是每帧都有标签，不会自动向其他帧传播；当前帧选择和回显仍有问题 |
| SAM2 | 规则及模型路径检测，`segment_video`明确抛未实现异常 | 放入权重不能直接获得全片分割能力 |

复现：6秒、2fps、12帧视频，默认检测第0/4/8帧，共3次；首帧无检测时，标签只留下2秒与4秒两条。调度模拟的800秒视频默认最多采样200帧，最后时间398秒，结果没有充分的截断标志。

**建议按任务选择，而不是统一要求所有视频逐帧：**

1. 视频分类/动作事件使用整片或时间区间标签；没有必要为了此目标每帧画框。
2. 帧目标检测明确选择“首帧 / 抽帧 / 逐帧”，每个约定帧都保存处理状态，含零检测帧。只首帧模式可用于快照或素材候选，应明确范围。
3. 跟踪/视频分割需要跨帧身份或掩膜；“首帧标注 + 模型传播 + 人工检查”可以作为未来流程，但目前没有实现传播能力。
4. 真正逐帧目标数据使用 `frame_index` 与解码时间戳PTS，增加上一帧/下一帧、时间轴和track_id。不能以±0.5秒的容差代替帧精度，也不能只用平均FPS解决可变帧率时间映射。
5. 长片允许分段继续和预算限制，但上限必须显式显示；帧覆盖率、人工核验率与目标检测数量分别计算。
6. 为少样本图像生成选取视频帧时，建立派生图像素材并记录视频ID、帧号、时间戳、来源组。当前生成引擎只生成图像，不是视频增强/生成引擎。

## 6. 建议实施顺序

1. **先约束数据契约和版本绑定**：固定sample_id、标签schema和坐标/时间/字符单位；禁止跨版本混配；隔离人工缓存；修多源覆盖与失败状态。旧文件先做兼容适配，不盲目批量改写历史标签。
2. **再修变换与划分**：图像/点云几何映射，文本offset_map，结构化清洗；持久化method；分组冻结验证/测试、只在训练集拟合统计量或补AIGC。
3. **补各模态真实闭环**：视频先把“抽帧目标框 + 按帧人工修正 + 覆盖率 + 导出”做准确，再决定跟踪/逐帧分割；语音路径、依赖和按段修正；雷达先确认真实字段，文本确认结构化字段。
4. **统一任务与可用性**：版本building/ready/failed、当前版本切换、普通任务持久worker、并发目录独占、工作流预检。保留现有少样本tmux/W&B与物理GPU7设置。
5. **最后补平台扩展**：真实融合、图谱/本体、消费端导出格式、标准人工审查、术语变换入版本、外部回写入库、索引及流式下载。

每一步验收应检查“内容及标签语义”而非只看HTTP200、任务completed或ZIP可下载。处理成功、合法空标签、算法失败、人工核验、符合查询需求需要分别记录；继续保留用户已确认的“自动标注后允许下载，标记待人工核验”。

## 7. 修改前仍需确认的产品选择

本轮不需要阻塞审计；实施扩展时需要确认，不能擅自开全量重算或GPU任务：

- 视频目标主要是抽帧检测数据、连续跟踪/分割，还是动作/事件？哪些片长需要逐帧，哪些允许采样？
- 雷达文件真实列分别代表什么，是否有真实速度、强度、采集时间及坐标标定？
- CSV/JSON/XML哪些字段是正文，哪些是结构/数值/已有标签？
- 目标训练消费端需要平台原生格式、图像COCO/YOLO、视频帧框/轨迹格式，还是ASR/实体任务格式？
- 授权访客能否建立个人工作副本；普通人工标注副本应共享还是私有？现有少样本隔离不应随此改变。

无需因为这些产品选择暂未确定而保留L01–L07的错误行为。后续可先修已有接口的正确性，再确认新增能力范围。
