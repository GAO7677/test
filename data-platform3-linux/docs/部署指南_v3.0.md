# 离线数据中台 全栈部署指南（v3.0）

适用工程：`data-platform1`（`data-platform` 的优化版）  
技术栈：FastAPI + MySQL 8.0 后端，Vue 3 + Vite + Element Plus 前端，PyInstaller 可打包为 Windows 单机程序。  
运行模式：离线内网/单机环境；运行时不需要访问互联网。

---

## 1. 交付包内容

```text
data-platform1/
├── backend/                    # FastAPI 后端
│   ├── app/                    # 业务代码：routers / services / models / security / config
│   ├── alembic/                # 迁移脚本（当前版本启动时自动建表/补列）
│   ├── models/                 # 模型文件目录：yolov8n.onnx 已内置
│   ├── requirements.txt        # 后端依赖（按 Python 3.8.8 / 3.10 / 3.14 分组锁定）
│   └── seed_demo.py            # 演示数据脚本（仅标准库 + numpy + soundfile，无 requests）
├── frontend/                   # Vue 3 前端源码
│   ├── src/
│   ├── package.json
│   └── package-lock.json
├── docs/
│   ├── model-deployment.md     # VAD/NER 模型放置说明
│   └── 部署指南_v3.0.md         # 本指南
├── build.py                    # PyInstaller 一键打包脚本
├── config.json.example         # 配置样例
├── README.md
└── CHANGELOG_v3.0.md
```

已修复的关键点：v3.0 VAD/NER 服务不再引用不存在的 `CONFIG`；演示脚本移除 `requests` 依赖；版本号统一为 v3.0.0。

---

## 2. 目标机要求

- 操作系统：Windows 10/11 x64（推荐）；开发联调也可用 Linux/macOS。
- Python：推荐 **3.10**；兼容 3.8.8 与 3.14。必须按所用版本准备离线 wheel。
- Node.js：仅用于构建前端，推荐 Node 18+；离线目标机不需要安装 Node。
- 数据库：MySQL 8.0（服务会自动建库 `data_platform`，字符集 utf8mb4）。
- 浏览器：Chrome / Edge。
- 磁盘：建议预留 5GB 以上（上传数据、日志、模型、导出文件会增长）。

> 完全离线目标机不要再执行 `pip install` 在线解析或 `npm install`。请在一台可联网的同版本构建机上先下载依赖/构建前端，再拷贝到目标机。

---

## 3. 在线构建机准备（一次性）

以下操作在可联网机器完成，选择与目标机一致的 Python 版本和 Windows 架构。

### 3.1 下载后端离线 wheel

```bash
cd data-platform1
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r backend/requirements.txt
mkdir wheelhouse
pip download -r backend/requirements.txt -d wheelhouse
# 如需要打包 exe，再下载 pyinstaller：
pip download pyinstaller -d wheelhouse
```

将 `data-platform1` 与 `wheelhouse` 一起拷贝到离线目标机。

### 3.2 构建前端产物

```bash
cd data-platform1/frontend
npm ci
npm run build
```

执行后必须存在：

```text
frontend/dist/index.html
```

> 若离线目标机完全不安装 Node，请保留构建好的 `frontend/dist` 目录并随工程一起拷贝；后端启动时会自动托管该目录。

## 4. 离线目标机部署（源码运行）

### 4.1 安装依赖

```bash
cd data-platform1
python -m venv .venv
.venv\Scripts\activate
pip install --no-index --find-links=wheelhouse -r backend/requirements.txt
```

### 4.2 配置 MySQL 与 config.json

启动 MySQL 8.0，并确认有一个可建库账号。首次启动会自动生成 `backend/config.json`；也可先复制样例：

```bash
copy config.json.example backend\config.json
```

`backend/config.json` 关键字段：

```json
{
  "database": {
    "host": "localhost",
    "port": 3306,
    "username": "root",
    "password": "123456",
    "dbname": "data_platform"
  },
  "upload_dir": "D:\\DataPlatform\\Uploads",
  "log_dir": "D:\\DataPlatform\\Logs",
  "jwt_secret": "<首次启动自动生成随机密钥并写回>",
  "server_port": 8000,
  "security": {
    "max_login_attempts": 5,
    "lockout_duration_minutes": 30,
    "session_timeout_minutes": 120,
    "allow_concurrent_sessions": true
  },
  "models": {
    "vad_path": "",
    "ner_path": ""
  }
}
```

说明：

- `jwt_secret` 保持占位即可，首次启动自动生成随机密钥并写回。
- D 盘不可用时，上传/日志目录自动回退到程序同级 `DataPlatform\` 并写回配置。
- 四项安全策略以后端数据库 `system_settings` 表为准，可在“系统管理”页面修改。

### 4.3 可选：放置 v3.0 增强模型

`backend/models/yolov8n.onnx` 已内置，用于图像/视频 COCO 检测。  
如需启用 v3.0 语音 VAD 与中文 NER：

```text
backend/models/silero_vad.onnx
backend/models/zh_core_web_sm/meta.json
```

下载/校验详见 `docs/model-deployment.md`。未放置时系统仍可运行，对应规则显示“模型未就绪”。

### 4.4 启动后端并自动托管前端

```bash
cd data-platform1/backend
..\.venv\Scripts\activate
python -m app.main
```

启动成功标志：

```text
[启动] 默认数据初始化完成
[启动] 服务地址：http://localhost:8000
```

浏览器访问 `http://localhost:8000`。若 8000 被占用，会自动顺延到 8001/8002 并在控制台打印实际端口。

### 4.5 验证

```bash
curl http://localhost:8000/api/health
# 期望：{"status":"ok","version":"3.0.0"}
```

登录后检查：

- 规则自动标注页能打开，且模型状态标签不报错；
- 数据获取层可新建语音/雷达/图像/视频/文本数据；
- 数据集、清洗、采样、质量评估、语义/标准、系统管理页面可访问。

## 5. 默认账号与安全要求

初始密码均为 `admin`，首次登录强制改密，不可跳过。

| 用户名 | 角色 | 权限概要 |
|---|---|---|
| sysadmin | 系统管理员 | 全部权限：用户、系统配置、日志、数据、预处理、标准 |
| admin | 管理员 | 数据与预处理 CRUD，查看用户与日志 |
| guest | 访客 | 默认仅查看公开级数据、无操作权限；可由 sysadmin 授予可见/可操作密级 |

上线前必须完成：

1. 修改三个默认账号密码；
2. 按实际人员创建账号并分配角色/密级；
3. MySQL 账号最小授权，禁止弱口令；
4. 备份 `backend/config.json`、MySQL 数据库、`upload_dir` 目录。

## 7. Windows 打包部署（PyInstaller）

在可联网的 Windows 构建机上：

```bash
cd data-platform1
python -m venv .venv
.venv\Scripts\activate
pip install -r backend\requirements.txt pyinstaller
# 若 frontend/dist 不存在且本机构建前端：
cd frontend && npm ci && npm run build && cd ..
python build.py
```

产物：

```text
dist\DataPlatform\DataPlatform.exe
```

部署到目标机：

1. 拷贝整个 `dist\DataPlatform` 目录；
2. 目标机安装并启动 MySQL 8.0；
3. 首次双击 `DataPlatform.exe` 自动生成 exe 同级 `config.json`；
4. 如打包后才补充模型，可放到 exe 同级 `models\` 目录；
5. 浏览器访问控制台打印的地址。

> `build.py` 已配置 `spacy` collect-all、`vad_service` / `ner_service` hiddenimports，并收集 `backend/models`。打包前放入 `silero_vad.onnx` 与 `zh_core_web_sm` 会一并打入。

## 8. 开发联调（非生产）

无 MySQL 时可用 SQLite 仅做页面/接口联调：


```bash

```

Vite 已配置 `/api` 代理到 `http://localhost:8000`。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 数据库初始化失败 | 确认 MySQL 已启动；检查 `backend/config.json` 主机/端口/账号/密码；确认账号有建库权限 |
| 页面 404 或只有 API 没有页面 | 未构建/未拷贝 `frontend/dist`；在构建机执行 `npm ci && npm run build` 后重新拷贝 |
| 规则自动标注页 500 | 多为 v3.0 服务导入问题；当前包已修复，重新解压/拷贝代码并重启服务 |
| `silero_vad` / `spacy_ner` 模型未就绪 | 按 `docs/model-deployment.md` 放置模型；检查 `config.json` 的 `models.vad_path` / `models.ner_path` |
| PyInstaller 打包缺 spacy 管线 | 确认使用 `python build.py`，其中包含 `--collect-all spacy` 与 hiddenimports |
| 端口被占用 | 默认自动顺延；或在 `config.json` 修改 `server_port` |
| bcrypt 登录慢 | 首次登录/改密时哈希成本为 12，属正常现象 |
