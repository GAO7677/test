# 视频标注工作台

## 使用流程

1. **选择方式**：逐帧手动标注，或首帧手动标注＋后续自动标注。
2. **多选输出文件**：目标框、分割 mask、点轨迹。
3. **类别＋画框**：顶部只有一个类别下拉栏，第一项是「＋ 自定义类别」，下面为已有类别。新类别保存到个人标签库、可跨数据集复用；界面不要求选择物体编号。
4. **提示框只用于首次分割**：画框后 SAM 生成 mask，工作台将结果框设为该 mask 的外接框；保留原提示框用于追溯。生成中、完成、失败显示醒目状态。
5. **修正准备结果**：SAM 就绪后重新画框只调整结果框，不重新分割、不清空 mask 或点。mask 可添加、擦除；未手动修改的框随 mask 更新为外接框，手动修改过的框保持不变。自动点从完整 mask 采样，不受独立结果框限制；在上方「调整采样点」点击已有点删除、点击画面添加，每物体默认上限8点；不再单设重新采样或一键清空按钮。修正 mask 后自动点重采样、手动点仅删除已擦除区域内的点。
6. **确认与启动分开**：确认标注只加入人工准备清单，可连续准备多个物体。逐帧模式点击「保存并预览」；首帧自动模式确认所有物体后点击「开始后台自动标注」，一次提交全部已确认物体，按当前输出类型和处理终点生成。最多10个物体；有未确认草稿时禁止提交。
7. 后台提交成功即冻结框、mask、点和输出设置，可「关闭，后台继续」、刷新或离开页面。在「标注历史与任务」查看进度，完成后「预览结果」并下载；留在工作台时也会自动加载完成结果，支持各物体预览。提交尚未成功时不可关闭。
8. 「修改」载入副本，取消保留原结果，确认修改不会自动启动。已有自动结果显示「重新自动标注」，确认全部准备结果后显式点击；从整体结果「继续修正」保留原标注方式，自动模式返回首帧，不再强制切到逐帧手动。后续帧直接修改仍是单帧手动修正；失败或取消的任务可从任务列表「修改并重试」，恢复该次提交的全部首帧准备结果。恢复输入沿用用户权限，管理员可查看。
9. **首帧与后续结果**：首帧精确保留确认后的框和 mask，后续帧框取 SAM 跟踪 mask 的外接框。修改首帧、输出类型或处理终点后，旧结果不再视为符合当前设置。自动结果仍需人工核验。
10. 删除需确认：逐帧模式删除该物体当前帧及其点，首帧模式删除该物体及后续结果，其他物体保留。尚未提交的准备结果和删除等编辑，可点击「保存当前标注」存成新版本；仅确认后直接关闭会提示未保存。后台成功自动创建结果版本，不需要另存才能下载。

重画、取消或切换文件后，过期 SAM 回调不会覆盖新草稿。完整版本下载包含全部物体；单物体预览只显示所选物体。后台依托现有 Web 服务执行：关闭页面不终止任务；若 Web 服务本身重启，未完成任务会标为失败，可恢复首帧输入后重试，不承诺断点续算。

## 预览叠加

- 进入结果预览时，用「预览叠加（多选）」选择目标框、分割mask、点轨迹；只列出当前结果已生成的文件类型，默认全选。
- 可任意组合，全部取消时只播放原视频。切帧和播放保留当前组合；重新进入预览恢复全选。
- 叠加开关仅影响显示，不改变标注数据、下载内容或后续生成设置。单物体预览的框、mask和轨迹均限定于对应物体。

## 输出与身份

- 目标框：人工帧默认使用 SAM mask 外接框，允许用户独立修正；后续自动帧由 SAM 跟踪分割区域计算外接框。这是用户指定物体的跟踪框，不是 YOLO 自动发现新物体，不受 COCO80 类别限制。
- mask：SAM 2.1 输出的逐帧 COCO 未压缩 RLE，按列编码，保留孔洞。
- 轨迹：CoTracker3 跟踪所指定的点，保存坐标和可见性。不同物体用 `track_id`，同物体不同点用 `point_id`。编号仅供内部保存；逐帧手动记录各帧结果，连续点跟踪使用首帧自动流程，不按相同类别名猜测物体对应关系。
- 自动处理结果标记「待人工核验」。人工改点仅替换该物体该帧的点；保留其他帧的原始模型来源、可见性和生成段。
- 「下载标注文件」提供 ZIP，内含勾选的 `annotation_exports/<视频名>_box.json`、`_mask.json`、`_trajectory.json`。数据集版本下载勾选标签时也包含这些文件。
- 完整 `_label.json` 通过 `manual_annotations` 独立保存人工确认清单及逐物体 `generation` 状态，并保留编辑所需中间信息及其他历史标注；独立导出文件按所选类型筛选，在下载时生成，不混入数据文件列表。

继续使用平台管理的模型，无 CVAT、新端口或常驻 GPU 服务：

- SAM 2.1 Hiera Tiny：源码 `/mnt/data/gaoya/agent-data/apps/video-tracking/sam2`，提交 `2b90b9f5ceec907a1c18123530e92e794ad901a4`。
- CoTracker3 online：源码 `/mnt/data/gaoya/agent-data/apps/video-tracking/co-tracker`，提交 `82e02e8029753ad4ef13cf06be7f4fc5facdda4d`。
- 权重：`/mnt/data/gaoya/agent-data/weights/video-tracking/{sam2.1_hiera_tiny.pt,scaled_online.pth}`。
- 推理环境：`/mnt/data/gaoya/agent-data/envs/video-tracking`，按既有配置只读复用基础 torch 环境。
- GPU 固定 118 物理 GPU7（UUID `GPU-439e8b22-75c0-55fc-283f-01f012c049ac`）；视频任务排队串行执行，低于 6GiB 空闲显存拒绝启动，不换卡、不停止他人进程。取消或结束后释放模型子进程。
- 复用账号、权限、AutoLabelTask 和 DatasetVersion。管理员可查看其他用户正式任务；草稿任务不混入正式结果列表。新增 `annotation_labels` 表只存个人标签，由既有建表机制创建。
- 旧单类型 API 与历史结果保留兼容；新工作台使用组合流程，不再展示旧的独立模型入口。

## 代码职责

继续在已有文件内维护，不增加平行工作台或通用状态框架：

| 文件 | 职责 |
| --- | --- |
| `frontend/src/views/ManualLabelView.vue` | 页面交互、草稿确认、版本加载、结果预览；模型任务与格式处理调用下列模块 |
| `frontend/src/components/VideoAssist.vue` | 单个自动任务的提交、轮询、取消和状态通知；丢弃取消、重试或退出后的旧响应 |

| `frontend/src/videoMask.js` | RLE 编解码、画笔/橡皮擦、mask 内点采样与筛选；不处理页面状态或请求 |
| `backend/app/routers/video_annotation.py` | 请求校验、用户权限和任务接口 |
| `backend/app/services/video_annotation.py` | 任务执行、模型子进程与结果版本合并 |
| `backend/app/services/video_exports.py` | 按勾选类型整理下载内容 |

## 范围与验证

固定帧率视频，单次自动处理最多 300 帧、10 个物体，每物体最多 32 点；首帧模式明确显示处理终点。长视频剩余帧不会被宣称已自动标注。尚不支持自动发现中途出现的新物体、自动转码或 MOT 专用导出。

预览是浏览器叠加，不额外生成渲染 MP4。模型结果需人工核验，短视频验收不代表全场景精度。

本次后台流程验证证据：`outputs_v1/data_platform3_linux/20261014_video_background/`；早期逐物体自动提交已被统一后台提交取代。具体通过项及发布状态见根目录 `CHANGELOG_LINUX.md`。
